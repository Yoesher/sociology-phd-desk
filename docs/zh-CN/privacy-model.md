# 隐私与加密模型

Sociology PhD Desk 采用本地优先设计：核心功能不要求账户或云服务。“本地”只表示应用要求浏览器把数据存在哪里；它本身不等于已经加密、已经匿名化、已经备份或已经满足机构合规要求。

下面区分四个容易混淆的保护层级。

版本说明：已发布的 [`v0.3.0`](https://github.com/Yoesher/sociology-phd-desk/releases/tag/v0.3.0) 位于精确发布 SHA [`bb0d32f`](https://github.com/Yoesher/sociology-phd-desk/commit/bb0d32fe99348204ba89a16d6469014ae38e0ecf)，使用 portable/standard v5 与 encrypted container/vault/registry v1；其 Service Worker 只预缓存应用静态资源，不会把工作区数据移入 Cache Storage。

## A. 浏览器隔离

普通工作台以常规结构化数据存入 IndexedDB。浏览器的同源策略通常会把它与其他来源和浏览器配置文件隔离，但凡是能够在本应用来源下执行的脚本和 Service Worker，都属于同一信任边界。同一来源下仅路径不同的应用，并不会因此成为彼此隔离的独立来源。

浏览器隔离不会加密研究内容。能够访问浏览器配置文件、开发者工具、同源脚本、具有足够权限的扩展程序、恶意软件或底层设备的人或程序，可能读取这些内容。清除网站数据、存储驱逐、配置文件损坏或设备丢失，也可能让唯一副本消失。

## B. 界面锁定

界面锁定会在应用中隐藏工作台，并要求协作运行的标签页停止写入。对于普通工作台，底层 IndexedDB 仍是明文，因此界面锁定不得被称为“加密”。

对于加密工作台，执行锁定的标签页会丢弃其内存中的派生密钥，并原子增加锁定轮次。锁定前打开的其他协作标签页在下一次刷新、写入或请求备份时，如果仍持有旧轮次，就会被拒绝。锁定无法远程覆盖每个其他标签页已经持有的明文或密钥引用。这是一种并发协调机制，不是抵抗恶意同源代码的访问控制边界。

重新加载或关闭已解锁的加密工作台，也会丢弃应用持有的密钥引用。不过，JavaScript 和浏览器无法保证物理内存中的每一份副本都已经覆盖清零。

如果注册表路由发生变化、管理器关闭、普通存储消失，或加密库的唯一记录缺失或认证失败，协作运行的应用会关闭或毒化该会话并清空其缓存快照。加密异步操作在每次等待存储或密码学处理前后都会核对生命周期 generation；关闭或锁定会先推进 generation 再清空状态，因此延迟完成的刷新不能把解密数据重新写回或复活已经关闭的运行时。这可以阻止陈旧的应用句柄重建存储或继续使用缓存明文，但不能对抗已经复制了明文的恶意代码。

## C. 加密工作台与加密备份

加密本地工作台只保存一个经过认证的密文容器，不保存明文研究业务表。口令只做 NFC 规范化，不去除首尾空格，也不改变大小写。PBKDF2-HMAC-SHA-256 使用 600,000 次迭代和每个容器独立生成的 16 字节盐，派生不可导出的 AES-256-GCM 密钥；每次写入都重新生成 12 字节 IV，并使用 128 位认证标签。格式元数据作为 AAD 一并认证。

加密库记录仍会明文呈现少量非研究协调信息：随机绑定 ID、存储修订号、锁定轮次、已提交密钥调用号、加密尝试总数、算法参数和密文长度。该加密库记录不包含工作台名称或口令校验值。除此之外，应用还会维护一个未加密的路由注册表，其中包含逻辑工作台 ID、规范显示名称、存储定位符、加密模式与生命周期状态、修订号、时间戳、自动锁定设置，以及迁移、清理、预配、待完成删除和中断转换状态。注册表不包含研究正文、内容派生哈希或口令校验值，但名称与活动时间本身也可能具有敏感性。口令错误和已认证数据损坏会故意返回同一种通用失败提示。

加密 `.sociologydesk` 备份会独立于本地工作台以及其他备份重新生成盐和 IV。其受保护头部不含工作台名称、绑定 ID 或研究时间戳，但解密后的 portable 载荷会包含导出时从注册表复制的规范显示名称；普通 JSON 导出也会明文复制同一名称。这种仅用于导出的复制不会重写活动研究快照，也不会增加工作台数据修订号。操作系统和文件系统仍可能暴露文件名、大小、位置和文件时间。恢复时先认证并严格验证整个备份，再使用新的逻辑工作台 ID 创建存储修订号为 0 的独立工作台；认证失败不会写入目标记录。

在已发布的 `v0.3.0` 中，新建加密库与备份承载 portable v5。已有 portable-v3/v4 密文必须先通过认证再迁移；本地加密库只有在完整 v5 容器写入并读回核验后才发布新状态。口令错误、篡改、加密失败、存储失败或读回失败都会保留旧密文。恢复旧备份只在内存中迁移，认证与完整验证通过后才写入新的 v5 加密库。container、vault database 与 registry database 的版本号仍是 1，不能与 portable 载荷版本混为一谈。

新建逻辑 ID、非首次启动的存储定位符与所有权令牌、加密绑定 ID、盐和 IV 都要求浏览器提供密码学安全随机数；缺少该能力时会直接失败。确定性的初始路由只用于让并发首次启动收敛，并不是秘密。

本版本没有口令重置或恢复密钥。若口令和所有可用备份都丢失，项目无法恢复明文。请按照所在机构的要求，在多个合适介质上保留并实际测试备份。文件扩展名不会自动带来同步或备份能力。

## D. 设备或运行环境失陷

静态加密主要用于提高从 IndexedDB 或加密备份复制出的密文被离线披露的难度。它无法保护已经解锁的会话免受恶意同源 JavaScript、被攻破的依赖或 Service Worker、高权限浏览器扩展、恶意软件、远程控制软件、系统管理员、截屏、剪贴板捕获或操作系统失陷的影响。这类攻击者可能在使用时取得口令或明文。

PBKDF2 会减慢猜测速度，但不能把弱口令或复用口令变强。数据库与备份大小仍可能泄露大致数据量。AES-GCM 能认证单个容器，却不能证明它就是最新容器：能够替换浏览器配置文件存储的人，可以重放一份更早但完整有效的加密记录，使工作台回滚。删除浏览器数据库只属于逻辑删除，不是可验证的安全擦除；文件系统快照、浏览器同步、备份和闪存磨损均衡都可能留下残留副本。

如果伦理审批或机构制度要求使用获批准的受保护系统，请勿在此存放参与者直接身份信息、重新识别密钥、同意文件或受控原始材料。匿名 ID 仍可能具有可链接性。应用加密本身不构成法律合规、伦理审批、留存合规，也不代表适合机密或高度敏感数据。

## 从明文工作台转换

转换分两个阶段。第一阶段在创建独立加密库之前，先把新的目标定位符持久保留在普通路由上。应用从实际存储中读回密文，完成解密、完整工作台严格验证、语义相等检查和普通来源复查后，才发布加密路由。若中断后预留的加密库仍存在，重试必须用所提供的口令完成认证并核对逻辑工作台身份；丢弃一个仍存在的暂存加密库也需要同样的认证和身份凭据。只有确认目标物理上不存在时，才可无口令清除空预留。若该阶段失败，明文来源仍是权威来源。

清理是在加密路由已经验证并打开之后，由用户另行确认并单独记录的后续步骤。应用会先提交仍在排队的研究写入；管理器随后要求当前已解锁的加密会话，并按加密目标与明文来源的真实物理数据库名以稳定的词法顺序同时取得两把排他锁。两把锁都保持期间，应用重新读回并认证当前加密库，检查来源数据库名没有被共享或别名占用，并核对其中保存的逻辑工作台身份，之后才能删除。物理数据库删除与注册表发布无法组成同一原子事务：删除前或删除过程中失败时，来源会继续记录为待清理；物理删除完成后若发布失败，也会保守地保留 `cleanup-pending` 标记，直到幂等重试验证数据库确实不存在并完成登记。“已移除”标记与浏览器删除成功都不构成“安全擦除”承诺。

## 工作台生命周期与删除恢复

预配、迁移、转换、清理和删除都依靠持久的注册表或台账记录，并在触碰物理数据库前核对数据库名的所有权；应用不会清空来源不明或被别名占用的数据库。删除工作台会先发布 `deleting` 标记，只有确认物理数据库不存在后才完成注册表登记。具备安全跨标签页协调时，启动会自动重试未完成的删除；否则工作台中心会继续显示该项目和明确的重试操作。该标记表示应用已核验到的状态，不是数据在取证层面已经消失的证明。
