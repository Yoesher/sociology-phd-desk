## 0.4.0 local-material and storage website update — 2026-10-04, verified S1 and final S2

This records the actual S1 deployment and public acceptance. [PR #57](https://github.com/Yoesher/sociology-phd-desk/pull/57) squash-merged reviewed head `098cd795092e1ce8fecc33379af493ba09ed78e8` with an explicit expected-head check as S1 main `1da2883c4fd7a54125e1cea3bf321cb5c7ecdb5a`; tree `b0b775eeb1e385205ad70c2686b36191515576e9` is unchanged from the reviewed head. Documentation closeout subsequently completed through PR #58 as final S2, independently verified below. Every later presentation/release-documentation revision requires its own exact-head/main checks and public build verification; final identity/evidence belong in its PR/external ledger, avoiding another commit solely to insert its own SHA. Use instructions are in [the bilingual local-field-maps/storage guide](docs/local-field-maps-and-storage-2026-10-04.md); decisions are ADR-026 through ADR-028 in [DECISIONS.md](DECISIONS.md).

- **LocalFieldMaps:** user-imported static PNG/JPEG only, maximum 2 MiB per image / 4 MiB per full workspace, each edge ≤ 8,192 and area ≤ 16,000,000 pixels. Bounded header/dimension/base64 validation and actual image decoding precede acceptance. Store original bytes with the workspace; EXIF/GPS metadata is not stripped. No bundled China geometry, administrative master catalog, online tiles, external map API, GPS acquisition or public map-image export.
- **Research linkage:** normalized image x/y link an existing same-project field site; selecting a marker shows linked visits/interviews and reuses existing edit/create flows. Click, keyboard and percentage entry are available; re-marking replaces that site's point. Normalized coordinates and aliases do not establish anonymity. Require entitled materials showing county-level or coarser research context, or anonymous public settings, without participant homes, exact participant locations or identifiers.
- **Non-destructive changes:** failed saves retain drafts and saved records; replacing an annotated image requires explicit clearing of old markers. Removing a map or marker preserves the site/visit/interview records. Referenced site deletion or project reassignment is protected. Project selection is still a display projection; persistence and both backup formats retain all projects.
- **Version axes:** portable workspace, standard database and authenticated encrypted payload v7; v6 → v7 adds an empty field-map collection without invented coordinates. Retain older standard and authenticated payload migration paths. Encrypted container, vault database and registry database remain v1. A v7 backup requires a v7-capable app; the earlier 0.3.1 app is not claimed to read it.
- **Attachments/capacity:** PDF limits increase to 10 MiB each / 20 MiB per workspace; download decoding is deferred until click. Full readable ordinary JSON remains limited to 32 MiB, including all projects, PDF/image base64 and metadata. New interactive growth beyond the budget is rejected; a legacy already-over-budget workspace may be read/migrated and saved without increasing its serialized size. Ordinary export over 32 MiB explicitly fails without truncation. Existing authenticated encrypted backup retains its 64 MiB ciphertext ceiling, independent PDF/image limits and complete snapshot. Ordinary file-import preflight remains 32 MiB; this is not permission to import arbitrarily large ordinary JSON.
- **Dates:** an open application refreshes local-calendar “today” at midnight, focus and return to visibility. It adds no notification permission or closed-webpage/background notification.
- **National map gates:** authoritative source, redistribution/license, project-review metadata and national completeness remain **BLOCKED / NOT TESTABLE**. The 2026-10-04 official-source recheck did not establish a deployable national asset/license/review/completeness chain. A blank local-image annotation tool has a different architecture from a public map service; that distinction is an architectural inference, not legal certification or a map-review exemption.

### Phase 3C architecture (released in `v0.2.0`)

- A schema-v1 `sociology-phd-desk-registry` database stores only local routing/recovery metadata. Canonical display name, timestamps, workspace kind/mode, auto-lock, migration/cleanup/deletion truth, interrupted-conversion reservation, schema versions, registry revision, and opaque storage locators remain plaintext; research content, passphrases, keys, verifiers, and content digests do not belong there.
- Each standard personal or synthetic-demo workspace has a separate IndexedDB database. Phase 3C introduced this boundary at standard/portable v3; published `v0.3.0` extends it through v4 Theory and v5 Zotero-provenance migrations. Concurrent first boots converge on deterministic seed routes. Fresh personal data is empty; only an exact pristine legacy fixture remains demo, while an edited legacy demo becomes personal and gets a separate pristine demo companion.
- An encrypted workspace has a separate schema-v1 vault database containing one authenticated ciphertext record and plaintext CAS coordinates. It has no research-domain tables or plaintext workspace name.
- Encrypted container v1 uses Web Crypto PBKDF2-HMAC-SHA-256 (600,000 iterations, fresh 16-byte salt) and AES-256-GCM (non-extractable 256-bit key, fresh 12-byte IV, 128-bit tag, canonical header as AAD). Formal `v0.3.0` uses portable/standard v5; the earlier website `0.3.1` uses portable/standard/authenticated payload v6; current website `0.4.0` uses those axes at v7. Container, registry database and encrypted-vault database remain v1.
- A session manager and access gate bind the UI to one ready workspace, keep encrypted keys runtime-only, unmount research routes while locked, and coordinate cooperating tabs without broadcasting passphrases, keys, or research content. Route invalidation, manager close, missing physical storage, or authenticated vault tamper poisons the affected session and clears its cached snapshot. Encrypted async operations recheck a lifecycle generation after awaited storage/crypto work, so close or lock prevents delayed refresh from reviving the runtime.
- Legacy-singleton migration and standard-to-encrypted conversion use physical-name preflight plus staged copy/read-back/validation/publication. Conversion durably reserves its encrypted target before creation; an existing interrupted target requires passphrase authentication and workspace-identity proof for retry or discard, while a confirmed-absent target can have its empty reservation cleared without a passphrase. Plaintext cleanup first flushes pending writes, then requires the current authenticated encrypted session and holds stable lexically ordered locks on the encrypted target and source physical database names while checking route, source identity, and aliases. Plaintext sources remain recorded until cleanup succeeds; deletion is recoverable logical deletion rather than secure erasure.

This architecture was merged through PR #14 and is included in the formal `v0.2.0` Release.

### Phase 3E architecture (released in `v0.2.0`)

- `TheoryMemo` is the only new theory-specific entity. It belongs to one project, has one of six locale-neutral types (`concept`, `mechanism`, `dialogue`, `counterargument`, `boundary`, `synthesis`), and may reference existing same-project ResearchQuestion, Claim, and Literature records by stable ID. Manuscript remains the writing entity.
- Missing endpoints, cross-project relationships, and duplicate IDs within any memo relationship array are invalid. A referenced project, question, claim, or literature record cannot be deleted until the memo relationship is removed. Deleting a memo removes only that memo and never its endpoints.
- Portable `WorkspaceData` and standard per-workspace IndexedDB storage are v4 in `v0.2.0`. The only v3 → v4 semantic change is `theoryMemos: []`; no old log, note, task, claim, or other text becomes a theory memo. Supported import/migration composes v1 → v2 → v3 → v4.
- Encrypted container v1, encrypted-vault database v1, and registry database v1 do not advance. Existing authenticated portable-v3 vaults or backups migrate only after authentication and complete v4 read-back validation; failure retains the old ciphertext and publishes no partial route/storage update.
- The stable task category is `Theory / Conceptual Work`. It is stored as a locale-neutral raw value and localized only for display.

### Phase 3F architecture (released in `v0.2.0`)

- Nine research-work primary modules have one URL-addressable secondary Smart View level, plus a separate Workspace & Settings utility area. Secondary views are derived presentation filters and do not add persisted status values or mutate research data when opened.
- Manuscript, Submission, and ReviewerComment remain independent entities. They are presented through one Manuscripts & Publishing area, with legacy manuscript/submission routes redirected to the complete publishing view.
- The application shell provides an active breadcrumb, context-aware Quick Add, compact keyboard-operable flyout, complete mobile More accordion, responsive desktop/mobile layouts, and true-empty personal-workspace onboarding.

## Known issues and technical debt

- Browser-local data still requires an explicit, tested backup practice. Ordinary JSON and standard-workspace IndexedDB are plaintext; `.sociologydesk` encryption does not create an automatic second copy.
- `v0.2.0` is formally released. Its public smoke is a LIMITED PASS: desktop module access, Chinese switching, one Chinese mobile More/no-overflow check, and zero application console warnings/errors passed, while further mobile expansion was NOT RUN after the browser bridge timed out. Do not relabel this as a complete public interaction pass.
- The local registry intentionally exposes workspace display names, timestamps, modes, auto-lock settings, migration/cleanup state, versions, and opaque storage locators. Encrypted storage does not hide approximate database or backup size.
- There is no account, cloud sync, password reset, recovery key, or secure-erasure guarantee. A forgotten passphrase and lost backups can make encrypted data unrecoverable.
- Applications at different paths under the shared GitHub Pages origin are not separate security origins. Encryption at rest cannot protect an unlocked session or a compromised device/runtime.
- China Research Map remains blocked on authoritative source rights, public-redistribution permission, project-specific map-review metadata, and testable national completeness. It is deferred and excluded from the released versions. The independent local-image tool does not supply nationwide province/city/county browsing, grant image rights, establish anonymity, or certify legal/map-review compliance; all four national gates stay BLOCKED.
- Complete edit/delete parity remains unfinished across modules. The 0.3.1 application adds task and literature viewing/editing; it does not establish complete deletion support or parity for Quantitative, Research Log, Manuscripts, Submissions, or Reviewer Comments.
- Released browser E2E covers the recorded critical multi-viewport workflows, alongside domain, portable-data, repository, conflict, migration, optimistic context queue, and nested-modal tests. The current-session PDF/project/deadline scenarios passed at both viewports; the earlier blocked launch remains historical evidence.
- Expand nested Workspace/confirmation Escape, scroll-lock, and focus-restoration coverage from the existing component test to automated browser tests.
- Formal `v0.3.0` uses portable/standard v5, the earlier website `0.3.1` uses v6, and current website `0.4.0` uses portable/standard/authenticated payload v7. Retain fixtures and upgrade tests from every supported prior version, including authenticated legacy payloads/backups. Older apps cannot read future-version backups.
- Issue #2 remains open work: retained `Evidence.claim` text is not an explicit Evidence↔Claim link, and Claim↔manuscript-location navigation is not implemented by Phase 3B.
- Phase 3B public static deployment evidence is complete, but real public interaction smoke remains unexecuted because browser control returned `instances=[]`; repeat it when a usable browser instance is available without retroactively calling the missing check a pass.
- Released Import Guard bounds portable JSON files and collection/total record counts. The 0.4.0 update adds full-snapshot growth/export budget checks while retaining legacy over-budget reads/migration and bounded encrypted preservation. PDF 10/20 MiB and map-image 2/4 MiB limits do not replace a large folder archive; full readable JSON can reach 32 MiB before individual attachment limits are reached. Independent attachment storage and chunked authenticated backups remain unimplemented.
- Accessibility, keyboard navigation, and cross-browser behavior need a dedicated audit.
- Zotero selected-metadata handoff is released. Other integrations and automatic PDF metadata extraction remain unimplemented and require scoped API/license/privacy review.
